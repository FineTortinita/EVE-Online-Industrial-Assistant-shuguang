### 0.2 功能缺口

- **制造计算**：没有「造还是买」的逐节点 / 按类别开关；没有边角料（整流程多出）的显式结果与抵扣；

## 1. 借鉴要点（实测提炼）

### 1.1 开明网「制造计算」—— 计算与拆解

1. **波次分解（逐级分解）**：制造 / 反应 / 行星开发**三条轨道**分列；每一列 = 「分解到这一步时手上的完整清单」。
   某物品若在别的分支更深处还会用到（黄色），**推迟到最深那一层统一开工** —— 即按「最大深度」分层、
   同层**先合并全部需求再一次性取整流程**。整流程多出的量以**负数（绿色边角料）**显示。
2. **造还是买**：按类别四个总开关（反应材料 自己做/买入、卫星原料 自己采/买入、行星产物 自己种/买入、燃料块 自己造/买入），
   再加**逐节点右键切换**、逐节点设 ME/TE/解码器。自采原料「不计价」（现金口径），旁边给市价参考。
3. **成本分项**：原料（主站卖价）+ 星系成本（EIV×指数×建筑加成）+ 设施税 + SCC 附加费 4% = 总成本；
   边角料按 `min(自制实际花费, 卖价)` 抵扣；收入分「挂卖单（扣销售税+中介费）」与「按买价直接卖」两档。
4. **生产步骤表**：每个作业一行 —— 流程数、物品估价(EIV)、指数、制造税、用时；汇总「最长单步 / 单线合计」。
5. **采购清单**：按类别分组（矿物 / 卫星材料 / P1 / P2 / 燃料块…），一键复制成「物品名\t数量」，游戏批量购买直接粘贴。
6. **参数条**：制造地点与反应地点分开（星系 + 建筑 + 设施税 + 手填指数 + 最多 3 个改装件，安等系数自动）；
   蓝图 ME/TE、技能与税（销售税/中介费）；「一起算其他成品」。
7. **诚实声明**：未校验盘口深度、未计物流与蓝图费、步骤按合并需求估算、实际须按工单上限拆批。

### 1.2 T2 商人助手 —— 人物与库存规划

1. **组号 + 子级**：母项（子级 0）与子项同组号；**改组号即合并**多个产品的子项（子项流程自动重算，缺行补、多余行置 0）。
2. **备料 = 预定占用**：勾了「备料」才读库存并**预定**；预定**按组号从小到大**依次分配（组号即优先级）。
   例：组 1 要 30 A、组 2 要 20 A、库存 15 → 仍缺 35，而不是 20。
3. **子项产出锁定**（2025-12 新版）：子项完成后产出被锁给它的母项，直到母项启动才解锁，防止低优先级组抢料。
4. **按库存减流程 / 子项自动调整流程**：任一子项参数（并行、蓝图等级、设施）变动 → 全组重新匹配流程数，考虑库存。
5. **填料总表**：按设施分组列需求量与充裕度 —— **红 = 缺，蓝 = 够，绿 = 暂缺但有规划会造出来补**。
6. **并行 + 大规模产线并行**：按产线数 / 按子线时长上限两种模式；甘特图显示同组反应线/制造线占用、夜间灰带。
7. **人物占用**：按人物显示产线占用（图形），启动小助手里选执行人物。
8. **成本账**：移动加权平均（所有入库：粘贴、订单成交、合同、制造产出、移库）；制造成本 = 子项提供 + 库存 + 市场购买 三源合并 + 启动费 + 蓝图费；
   **移库**继承来源机库成本；机库可设「材料来源机库」自动移库。

> 现有代码已有：组号/子级、并行、大规模并行、甘特图、人物占用、加权平均成本、启动扣料/完成入库带成本。
> **缺的是 1.2 的 2/3/4/5/8(移库) 和 1.1 的几乎全部**。

### 1.3 T2 商人助手逆向结论（2026-11-17，ILSpy 反编译 2.0.9488）

> 完整报告（含混淆名 → 含义索引、`文件:行` 证据、伪代码）放在**仓库外** `F:\re_tools\reports\01~04_*.md`，
> 不入公开仓库（第三方商业软件；报告含其服务端架构信息）。下面只记会影响我们设计的结论，全部为自行转述的算法，不含其源码。

**A. 分解引擎（01 报告）**
- 不是递归：每个**组**一张需求总账（按物品 ID 一行，`Requires / 库存与在产 / byus / matfor`），按轮次迭代至不动点。
  同组所有母项的需求**落同一行** → 共享中间件天然合并；中间件需求增加时只把 `新取整 − 旧取整` 的**增量**下传。
- `子级 = 沿 matfor 到母项的最长路径`（与开明网「推迟到最深层统一开工」同一思想）。
- 买/造判定：无配方 / 反应且未勾「分解反应」/ 行星产物且未勾「分解行星」/ 燃料块不分解 / 用户锁定 → 买。
- 每行流程 = `ceil(ceil(max(0, 需求 − 库存 − 在产) / 单流程产出) / 并行)`；材料逐线取整再 × 并行。
- **任何编辑（并行、等级、设施、组号、期望时长）= 带现有子项约束重跑整组引擎 → 与现有行对账**：缺行补、
  多余行 Runs=0 并退出备料（或按设置删除）、运行中 / 持有锁定产出的行不动、同物品多行按目标并行分摊。
- 期望时长：只增不减地把流程补满到整 H 小时周期；边角料 = 本组产出 − 本组消耗。
- 不足（不照搬）：材料取整用字符串切分、无 `round(·,2)`；改组号不清理旧组子项；硬编码 typeID。

**B. 库存与占用（02 报告）**
- 库存行只存 `(物品, 机库, 数量, 移动平均单价)`；**占用 / 冻结 / 在售量全部不落库，每次刷新重算**。
- 分配顺序：组号升序 → 组内**子级降序**（子项先算）；只有勾「备料」的计划参与；只从**本计划设施的机库**取。
  单计划取料来源顺序：①运行中子项产出 → ②已完成子项冻结产出 → ③机库闲置库存 → ④计划中子项将产出 → ⑤缺口。
- **子项产出冻结**：子项（子级>0）完成时产出不入库，记在该计划行 `tocargo`（「规划冻结」）；母项启动时直接消耗；
  母项不再需要或行被删时余量作「子项残余」入库。
- 填料总表：`需填 = max(0, 总需 − 在产 − 现有)`，`充裕度 = 现有/总需`、`在产率 = 在产/总需`；蓝 ≥1、绿 = 两者和 ≥1、红 = 其余。
- 采购小助手：各设施缺口汇总 − 未被母项消费的计划产出富余；仓检 = 其他机库**闲置**量、单检 = 自己卖单量，都只提示不改数。
- 成本：移动平均（出库不改单价、零成本入库不摊薄）；启动时 `运行成本 = 启动费 + 蓝图费 + 库存料成本 + 冻结子项产出成本`，
  完成时 `单价 = 运行成本 / 产出数`；移库按来源单价；剪贴板对账出 NEW/CHANGED/REMOVED，机库设了「材料来源」则自动生成同量移库。
- 其缺陷（我们要修掉）：填料总表没算冻结量 → 冻结件被当成要买；运行成本漏算「运行中子项供料」成本；
  占用从不跨机库（同星系也不行）。

**C. 人物与排程（03 报告）**
- 槽位 = `1 + 两个技能等级`（制造 3387/24625、科研 3406/24624、反应 45748/45749）—— 与我们 `char_capacity` 一致。
- 伪人物 `[技能全0]` / `[技能全5]` 用于假设核算。占用是**当前快照**，按状态分档：运行中、待启动、需填料、**等待子项（不占槽）**。
- 自动派人 = 贪心：先试指定人物，再找技能达标且剩余槽够的人物。
- 大规模并行：**按线数**模式把每行时长折算成「周期」（单流程秒 × 最少流程 / 周期长 / 3600），
  `每线负担 = max(1, 同类周期总数 / 线数)`、`并行 = ceil(周期 / 每线负担)` 且不超过流程数，逐子级处理、取整差额下传；
  **按时长上限**模式不断加并行直到单线时长 < 上限（其实现单流程超限时死循环 —— 我们要加终止）。
- 甘特：同组最深子级先排，母项从其子项最晚完成开工；「同子级对齐」时同层统一从下层最晚完成开工；**不受人物/槽位约束**。
- 公式与我们计划一致：启动费 `EIV × 流程×并行 × (指数×建筑 + 税 + SCC 0.04)`；改装件安等 1.0 / 1.9 / 2.1，反应改装件 00/虫洞 1.1；
  植入体按「前缀-系数」作用于制造 / ME / TE / 拷贝 / 精炼时间；发明 `基础 × (1 + 两科学技能/30 + 加密/40) × (1 + 解码器)`。

**D. 数据与导入（04 报告）**
- 用户数据全在作者的远端 MySQL（每用户 13 张私表，后台队列 upsert），**不用 ESI 拿资产/作业/蓝图** —— 全靠剪贴板粘贴、
  游戏 `Marketlogs` 导出 CSV、订单快照差分推断成交（NEW/CHANGED/REMOVED/EXPIRED）、客户端缓存。
- 我们已有 `order_events` 台账（v18）与订单差分，可直接接到「买单成交 → 自动入库带成本」。

**逆向后对本计划的修正**
1. 占用**不建 `plan_reservations` 表**，改为纯函数每次重算（T2 已验证可行，避免占用表与计划表不同步）；只需落库 `备料` 开关与「子项冻结产出」。
2. 引擎用「最长路径分层 + 逐层合并取整」（等价于 T2 的不动点迭代，但单遍、确定性、易测）。
3. 「任何编辑 = 带约束重跑 + 对账」作为计划侧唯一的更新路径，替代现有多处零散重算。
4. 修正 T2 的三个缺陷（填料总表含冻结量、运行成本含子项供料、可选同星系跨机库取料）。

## 2. 目标架构

```
domain/industry_calc.py   ← 新：纯函数「工业计算引擎」（无 DB/Qt），取代 3 套展开器的计算核心
   输入  BuildRequest：targets[(type, qty)]、per-type 覆盖（造/买、ME/TE/解码器、设施档）、
         类别默认（反应/卫星/PI/燃料块 造或买）、设施档（制造/反应各一：建筑、改装件、安等、指数、税）、
         人物技能+植入体、库存池（可选，带优先级）
   输出  BuildResult：
         waves[track][level] 每层完整清单（含负数边角料）
         jobs[]   每作业：activity、runs、jobs拆批、EIV、指数、各项费用、单作业时长
         raws[]   按类别分组、需买量、单价、是否自采不计价
         leftovers[]  边角料与抵扣值
         cost     原料/星系成本/设施税/SCC/总计/单件/抵扣后
services/industry_calc_service.py ← 新：只做「从 reference/blueprint/market 库装配 BuildRequest + 调引擎」
   调用方（满足 ADR-001 ≥2 个）：查询页 BOM（bom_expander.py:100）、计划拆解（plan_rebuild.py:252）、
   拆解预览（plan_decompose.py:58）、采购汇总（plan_aggregator.py:764）、新「制造计算」页
```

**算法要点**（游戏机制）：

- 单作业材料：`max(runs, ceil(round(base × runs × (1−ME/100) × 建筑 × Π(1−改装件×安等系数), 2)))`；
  并行 N 线 → 逐作业取整再求和（与现有启动闸门同口径）。
- 分层：对 DAG 求每个类型的**最大深度**；从浅到深逐层：本层所有需求（来自所有母项、所有成品）合并 → 扣库存池 →
  `runs = ceil(净需求/单流程产出)` → 产生下层需求 → 记 `surplus = runs×产出 − 净需求`（边角料）。
- 作业费：`EIV × (指数 × 建筑费用加成 + 设施税 + SCC 4%)`（制造与反应**同一公式**，EIV 用 adjusted_price）。
- 时长：`base × 技能 × 植入体 × (1−TE) × 建筑时间 × 改装件时间(×安等)`；反应用反应技能与反应建筑。
- 环检测、最大深度保护沿用现有实现。

**库存规划层**（`user.db` 迁移，走 `schema_migrations.py`）：

- **占用不落库**（见 1.3 修正 1）：`domain/reservation.py` 纯函数 `allocate(plans, stock, frozen) → 每计划每料 {来源: 量} + 缺口`，
  顺序：组号升序 → 子级降序；来源：运行中子项 → 冻结子项产出 → 本设施机库闲置 →（可选）同星系其他机库 → 计划中子项 → 缺口。
- `production_plans.reserve_materials`（备料开关，默认 1）、`production_plans.frozen_output_qty` + `frozen_output_cost`
  （子项完成后的冻结产出，母项启动时消耗，余量作「子项残余」入库）。
- `inventory_ledger(ts, hangar_id, type_id, delta, unit_cost, reason, ref_id)`：所有入/出库留痕（粘贴、购买、启动、完成、移库、手改），
  支持撤销与成本追溯；加权平均成本仍存在 `inventory_items.cost_price`。
- `hangars.source_hangar_id`（材料来源机库，自动移库）、`hangars.char_name`（可选：仓库归属人物）。

## 阶段 4 细化（2026-11-17，开工前定稿；按 CLAUDE.md 要求经 plan-auditor 审）

**范围收窄**：不改 `start_plan` / `complete_plan` 的扣料 / 入库时序（2627 行、测试最密的模块）；占用只在**展示与判定层**算，
冻结只加一条「子项完成时产出暂不入库」的分支。

### 4.1 schema v24→v25（只加列，`_add_columns`，幂等）

| 表.列 | 类型 / 默认 | 语义 | 存量回填 |
|---|---|---|---|
| `production_plans.frozen_qty` | INTEGER DEFAULT 0 | 子项完成后**未入库**、锁给母项的产出数量 | 0（历史完成的子项产出早已入库，不追溯） |
| `production_plans.frozen_cost` | REAL DEFAULT 0 | 冻结产出的单件成本（启动快照口径） | 0 |
| `hangars.source_hangar_id` | INTEGER DEFAULT NULL | 材料来源机库（移库时成本继承来源） | NULL |

- **备料开关复用既有 `materials_ready`**（计划表第 0 列「备料」勾选，已存在、已落库），不新增列。
- **不建占用表**（见 1.3 修正 1）、**不建 inventory_ledger**（原计划有；移库与冻结都能在现有 `add_item`/`deduct_item` 上完成，
  台账属于没有现存调用方的新抽象，ADR-001 不通过，延后到真有「撤销移库 / 成本追溯」需求时再加）。

### 4.2 行为

1. **占用分配**（`domain/reservation.py`，纯函数）：输入 = 活跃计划（备料勾选的 pending 行）× 每行材料需求、机库库存、冻结产出、
   在产子项将产出；顺序 = 组号升序 → 子级降序 → id；来源 = 运行中子项 → 冻结产出 → 本机库闲置 → 计划中子项 → 缺口。
   输出每行每料 `{stock, frozen, child_running, child_planned, short}`。
2. **展示接入**：计划表状态列「材料不足」改用分配结果（低组号先占）；填料总表三态（蓝 = 现有够、绿 = 加上子项将产出够、红 = 缺），
   按设施（材料机库）分组；仓库页「规划占用」读同一份分配。启动闸门 `check_materials` **保持现口径不变**（只看本机库 + 子线将产出），
   避免改变能否启动的判定 —— 占用只影响「谁先拿」的提示与采购量。
3. **子项产出冻结**：`complete_plan` 对 sub_level>0 且有活跃母项引用的行，产出写 `frozen_qty/frozen_cost` 而不入库；
   母项 `start_plan` 时，本组冻结量先补进母项材料机库（`add_item`，冻结成本）再走原扣料流程 —— 扣料逻辑零改动；
   母项结束 / 删除 / 子项不再被引用时，余量作「子项残余」入库（`remove_completed_children` 删行前处理）。
4. **移库**：仓库页「移到机库」改为按数量移动、成本继承来源（现有 `move_items` 已是加权平均继承，补「按数量部分移动」）；
   设了 `source_hangar_id` 的机库在剪贴板对账出现新增物品时，提示「来自来源机库」一键移库。

### 4.3 验证

- 分配：`tests/test_reservation.py` 参数化 —— T2 例「组 1 要 30、组 2 要 20、库存 15 → 缺 35」、组号优先、子级降序、冻结优先于库存、
  未勾备料不参与。
- 冻结：`test_plan_execution` 加 1 条端到端（子项完成 → 不入库、frozen_qty；母项启动 → 冻结量被消耗、成本带入）。

### 4.4 审计结论与收窄（2026-11-17，plan-auditor：approve-with-changes，建议拆分）

采纳审计「计划可以更小」：**阶段 4a 不迁移、不改 `plan_execution.py`**。

- **冻结改为计算口径**：已完成子项的产出今天本来就入库；分配时把 `min(该子项产出, 引用母项材料机库里该物品的库存)`
  当作「冻结产出」来源、**从共享库存池里先扣出来**，只给引用它的母项所在组（按 `source_mother_ids` 找组，跨组共享件也覆盖）。
  每次刷新重算，与 T2「占用不落库」同一思路；物理冻结（`frozen_qty`/`frozen_cost`、启动时回补、删行释放）连同审计列出的
  10 处约束推迟到 **阶段 4b**，只在实际出现「别组抢走子项产出」时再做。
- **`source_hangar_id` 推迟**：「来自其他机库」逐行移库已存在（`review_bridge.py:784`、`inventory_manager.py:761`），自动来源提示无现存调用方（ADR-001）。
- **备料开关**：复用 `materials_ready`（语义本就是「备料中」）；它默认 1 → 实际上人人参与、组号决定优先级。
  未勾备料的待生产行**回退原 `check_materials` 判定**，状态列不丢。
- 启动闸门 `check_materials` 不变；占用只影响「谁先拿」的提示、填料总表与状态列。
